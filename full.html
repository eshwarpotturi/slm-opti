The finding

A small model becomes dependable when the system around it does the checking.

On two financial tasks, small open models were right about half the time on their own. With checks, fine-tuning and selective escalation they reached 80% and 89%, close to a large model at a fraction of its cost.

Why it works

Three moves did it, and they are the same on both tasks.

None of them is a better prompt. Each one is code or training around the model.

01 · CHECK

Verify every answer in code

48 → 3

wrong money-moving actions in 150 payment requests, once rules check each action against the account before it runs.

02 · TUNE

Train the model on the task

51% → 80%

on payment requests after 800 training examples on a free GPU. On financial reports the same step lifted trusted answers from 86% to 92% correct.

Send only doubtful cases up

The five layers

Each is code around the model. None changes the wording of the prompt.

  1. Reply check. The reply must be valid and fit the template for the chosen action, with one retry.
  2. Record lookup. Code finds the account records the request refers to. IDs can only come from those.
  3. Split and search. A message with several requests is split, and the model sees only the most relevant actions.
  4. Rule check. Every proposed action is tested against the state of the account, with one chance to correct.
  5. Escalation. When repeated attempts by the small model disagree, a large model takes the request.

Honest account

What did not work, and where a language model is not needed.

On financial reports, six code-only techniques did not beat the model working alone

100 practice questions, one small model. The mistakes are choosing the wrong row or year, which a calculator cannot repair. A few points either way is within chance at this sample size.

On payment requests, classical machine learning matched the small language model

The task turned out to be mostly sorting requests into types. A text classifier with hand-written rules, trained in seconds, did as well. The rule check lifted both to 89%.

What this means for choosing a task. A language model earns its place where the answer has to be read and reasoned out of a document, as with the financial reports. Where requests fall into a fixed set of types, try a classifier first and keep the rule check.

Limits of these results

  • On financial reports about half the questions still go to the large model, and the benchmark supplies the right page. Finding that page in a full report is not tested.
  • The payment requests were generated for this study and reworded by a separate model; the financial questions are from a public benchmark.
  • All figures are single runs on unseen test sets of 297 and 150 items. The fine-tuned pair's financial result combines recorded answers from separate runs.
Models: Gemma 3 4B, Ministral 3B, Llama 3.1 8B (small); Claude Haiku 4.5 and Claude Sonnet 4.5 (large). Financial data: FinQA, Chen et al., 2021, MIT licence. Costs are list prices per 1,000 requests; the fine-tuned model's own running cost is not included.
